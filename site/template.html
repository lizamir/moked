עוזר AI שעונה רק ממה שקרא

מוקד עונה בעברית על שאלות על בינה מלאכותית. הוא לא עונה מהזיכרון: הוא מחפש במדריך, מציין מאיפה לקח כל משפט, ואומר "לא יודע" כשהתשובה לא כתובה שם.

הבעיה: צ'אט רגיל עונה גם כשהוא לא יודע

מודל שפה מרכיב תשובה שנשמעת הגיונית. כשאין לו מידע הוא לא נעצר, וכך נולדות תשובות בטוחות ושגויות. הפתרון של מוקד פשוט: קודם קוראים, אחר כך עונים.

צ'אט רגיל: מבחן מהזיכרון

עונה לפי מה שזכור לו מהאימון. אי אפשר לדעת מאיפה הגיעה התשובה, והוא ימציא מספר או מקור אם זה נשמע סביר.

מוקד: מבחן בספר פתוח

מחפש קודם במדריך, מקבל את הקטעים המתאימים, ועונה רק מתוכם. ליד כל משפט מופיע המקור, ואם אין קטע מתאים הוא אומר שאין לו תשובה.

ההדגמה: לעקוב אחרי שאלה אחת

בוחרים שאלה ורואים מה קורה לה בדרך לתשובה. החיפוש שמוצג כאן אמיתי: אותו קוד של הפרויקט רץ עכשיו בדפדפן שלכם.

1

מפרקים את השאלה למילים

בעברית אותיות כמו ו', ב', ה' נדבקות למילה. כדי ש"במסלול" ימצא גם "מסלול", הקוד מקלף אותן ומחפש גם את הצורה הקצרה. מילים נפוצות כמו "מה" או "של" לא עוזרות לחיפוש, ולכן מדלגים עליהן. הצורות הקצרות לא תמיד מילים אמיתיות, וזה בסדר: הן רק צריכות להתאים לאותה צורה במסמכים.

2

שני חיפושים במקביל

חיפוש אחד מוצא קטעים עם אותן מילים. חיפוש שני מוצא קטעים עם אותה משמעות, גם אם המילים שונות. לכל אחד חולשות משלו, ולכן מריצים את שניהם. לחיצה על קטע פותחת את הטקסט שלו.

      מאחדים לרשימה אחת

      קטע ששני החיפושים דירגו גבוה עולה לראש. חמשת הקטעים האלה הם כל מה שהסוכן יקבל לקריאה.

        הסוכן קורא ועונה

        הסוכן הוא מודל שפה (Claude) שמקבל את הקטעים ואת ההנחיה לענות רק מתוכם ולציין מקור. אם הקטעים לא מספיקים, הוא יכול לחפש שוב בניסוח אחר.

        חשוב לדעת: שלב 4 לא רץ בעמוד הזה, כי הוא צריך מפתח API בתשלום. מה שמוצג הוא התשובה שהמבחן מצפה לה, מתוך קובץ הבדיקות של הפרויקט. שלבים 1 עד 3 אמיתיים.

        איך זה עובד, בחמישה צעדים

        לשיטה הזו קוראים RAG: לתת למודל לקרוא לפני שהוא עונה.

        1. חותכים את המדריך

          כל מסמך נחתך לקטעים קצרים לפי הכותרות שלו, כך שכל קטע עוסק בנושא אחד.

        2. מחפשים פעמיים

          פעם לפי מילים ופעם לפי משמעות, ומאחדים את התוצאות.

        3. מדרגים מחדש

          מודל קטן ומהיר קורא את המועמדים המובילים ומסדר אותם לפי התאמה לשאלה.

        4. הסוכן עונה

          מודל גדול קורא את הקטעים, כותב תשובה קצרה ומציין מקור לכל משפט.

        5. בודקים במבחן

          20 שאלות קבועות רצות אחרי כל שינוי בקוד, ואם האיכות יורדת, הבדיקה נכשלת.

        האם זה באמת עובד? המספרים

        לכל שאלה במבחן ידוע מראש איזה קטע במדריך עונה עליה. הגרף מראה באיזה אחוז מהשאלות הקטע הנכון הופיע בין חמש התוצאות הראשונות, בכל שיטת חיפוש.

        המספרים נמדדו על 17 השאלות שיש להן תשובה במדריך. זה מבחן קטן, ולכן הוא מראה כיוון ולא אמת מוחלטת.

        מה יש בפרויקט

        הכול כתוב בקוד, בשפת TypeScript, בלי כלי גרירה מוכנים.

        מנוע חיפוש לעברית

        מבחן החיפוש רץ ונבדק

        הסוכן והדירוג מחדש

        החלקים שמדברים עם Claude: כתיבת התשובה, דירוג הקטעים ומבחן התשובות.

        כתוב, ממתין למפתח API

        מילון קצר

        המילים שחוזרות בפרויקט, בעברית פשוטה.

        מודל שפה LLM

        תוכנה שלמדה מהמון טקסט לחזות איזו מילה תבוא עכשיו. Claude ו-ChatGPT בנויים על מודלים כאלה.

        RAG

        שיטה שבה המערכת מחפשת קודם במסמכים, מצרפת את מה שמצאה לשאלה, ורק אז המודל עונה. מבחן בספר פתוח.

        קטע chunk

        חתיכה קצרה של מסמך. מחפשים בקטעים ולא במסמכים שלמים, כי כך החיפוש מדויק יותר.

        חיפוש מילות מפתח BM25

        חיפוש שמוצא קטעים עם אותן מילים שבשאלה, ונותן יותר משקל למילים נדירות.

        הטמעה embedding

        רשימה של מספרים שמייצגת את המשמעות של טקסט. טקסטים עם משמעות דומה מקבלים מספרים קרובים, וכך מחפשים לפי משמעות.

        חיפוש היברידי

        הרצה של שני החיפושים יחד ואיחוד התוצאות לרשימה אחת.

        דירוג מחדש re-ranking

        שלב נוסף שבו מודל קורא את התוצאות המובילות ומסדר אותן לפי מידת ההתאמה לשאלה.

        סוכן agent

        מודל שפה שמקבל מטרה וכלים, ומחליט בעצמו אילו צעדים לעשות. כאן הכלים הם חיפוש במדריך וקריאת מסמך.

        MCP

        תקן אחיד לחיבור מודלים לכלים, כמו שקע USB. שרת MCP מציע יכולות, ואפליקציות שתומכות בתקן מתחברות אליו.

        מבחן eval

        רשימה קבועה של שאלות עם תשובות ידועות. מריצים אותה אחרי כל שינוי כדי לדעת אם המערכת השתפרה או נפגעה.

        הזרקת פרומפט prompt injection

        טקסט ששותלים בתוך מסמך כדי שהמודל יחשוב שזו הוראה. במדריך של מוקד יש מלכודת כזו בכוונה, והמבחן בודק שהסוכן לא נופל בה.

        API ומפתח API

        API הוא הדרך שבה תוכנה אחת מדברת עם תוכנה אחרת. מפתח API הוא הסיסמה שמזהה אתכם מול השירות, ולפיה מחייבים על השימוש.
